# gen.py / strictcli_support.py architectural coupling

## Context

`gen.py` has a stale-cleanup pass that deletes `.md` files from `docs/` that don't match expected output paths. `strictcli_support.py` generates CLI command pages. These two systems are loosely coupled -- gen.py doesn't know about strictcli_support's expected output files when deciding what to delete.

## Problem

In selfdoc 0.5.0, the description preservation fix was added to `gen.py` for module pages. But CLI pages (generated by `strictcli_support.py`) were still being deleted by gen.py's cleanup pass BEFORE regeneration, destroying preserved descriptions. This required two additional releases (0.5.1, 0.5.2) to fix -- each fix surfaced another bug in the boundary between the two modules.

## Root cause

gen.py's cleanup and strictcli_support's generation are not coordinated. gen.py decides which files to keep based on its own knowledge of expected pages, but it doesn't consult strictcli_support for the CLI page list. The fix in 0.5.2 works (CLI pages are now excluded from cleanup), but the boundary is fragile -- adding a new page type would hit the same issue.

## Proposed direction

gen.py should collect ALL expected output filenames (from both its own module pages and strictcli_support's CLI pages) before running cleanup. The cleanup pass should be the last step, not an early step. This way, every page generator registers its outputs first, and cleanup only removes files that no generator claims.

## Effort

Medium. Requires restructuring the generation pipeline so that output registration happens before cleanup, and all generators contribute to a single "expected files" set.
