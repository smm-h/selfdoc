# Auto-commit generated docs after `selfdoc gen`

## Problem

When `selfdoc gen` generates or updates docs files (e.g., CLI reference, internal module docs), the generated files are left as untracked or modified in the working tree. The user has to manually commit them, which is easy to forget. This leads to repos accumulating untracked generated docs that only get noticed at release time.

## Expected behavior

After `selfdoc gen` writes files, it should offer to auto-commit them (or do it unconditionally with a `--commit` flag). The commit message should be standardized (e.g., `docs: regenerate selfdoc output`) and could use an `Autogenerated: true` trailer for changelog exemption.

## Scope

Small. Add a `--commit` flag (or auto-detect if in a git repo and commit automatically). Use `git add <files>` + `git commit` on the specific files that were written/updated.
