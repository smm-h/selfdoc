# `selfdoc gen` cannot auto-commit in a non-interactive shell

## Context

`selfdoc gen` auto-commits its generated output by default (documented as the normal development path: "run bare `selfdoc gen` and it auto-commits with the `Autogenerated: true` trailer"). Internally it shells out to `safegit` to make that commit.

## Problem

In a non-interactive shell (agent sessions, CI, any pipeline without a TTY), the internal `safegit` invocation fails with:

```
stdin is not interactive; pass --yes to confirm
```

`selfdoc gen` exposes no `--yes` flag, so there is no way to satisfy that prompt from the command line. The result: bare `selfdoc gen` cannot complete its documented default behavior outside an interactive terminal. The generated files are written but left uncommitted, and the caller has to notice and commit them by another route.

This makes the documented "always run bare `selfdoc gen`" guidance impossible to follow in automated contexts, and it silently shifts commit responsibility to the caller.

## Possible solutions

1. **Pass `--yes` through to the internal `safegit` call unconditionally.** The commit selfdoc makes is machine-generated and fully determined by the tool; there is no user decision to confirm. Pro: no new surface, fixes every non-interactive caller at once. Con: removes a confirmation that may exist deliberately for interactive use.
2. **Add a `--yes` flag to `selfdoc gen`** that forwards to `safegit`. Pro: explicit, matches the ecosystem convention of verbose/explicit invocation. Con: callers must know to pass it; the documented bare form still fails non-interactively.
3. **Detect non-interactive stdin and forward `--yes` automatically**, leaving interactive behavior unchanged. Pro: the documented bare command works everywhere. Con: behavior differs by environment, which cuts against "same input, same behavior every time."
4. **Surface a clearer error** telling the caller exactly what to run instead. Strictly worse than fixing it, but better than the current opaque failure.

Option 1 or 3 looks most correct; option 2 alone does not fix the documented default path.

## Affected files

- The `gen` command implementation (wherever the internal `safegit` commit is invoked)
- The auto-commit helper shared by `gen`/`build`, if one exists
- Docs describing the bare `selfdoc gen` auto-commit workflow

## Effort

Small — likely a one-line argument change plus a regression test that runs `selfdoc gen` with stdin closed and asserts the commit lands.
