# 0.4.5 regression: stopped honoring module docstrings as page descriptions

## Problem

Starting in selfdoc 0.4.5, `selfdoc gen` no longer uses the source module's module-level docstring as the page's frontmatter `description` field. Instead, it injects a generic template:

> "API reference for the `<module>` module -- auto-generated documentation covering public functions, classes, and type signatures."

Every module page now has effectively the same description with only the module name varying.

## Impact

In rlsbl alone, 70 module pages lost their bespoke, informative descriptions during a single `selfdoc gen` run. This silently degrades:

- SEO (search engines see boilerplate instead of distinct, query-relevant copy)
- AI-citation discoverability (LLMs that index docs lose the per-module signal)
- Human scanability of the docs site index / per-page hero copy

This affects every selfdoc-using project that has upgraded to 0.4.5 or later. The damage compounds on every `selfdoc gen` run because the generic template overwrites any manual fix-ups.

## Example

`rlsbl/utils.py`'s docstring is:

> "Git helpers, version bump logic, changelog section extraction, and other shared utilities used across all rlsbl commands and targets."

After upgrading to 0.4.5 and running `selfdoc gen`, that description is gone -- replaced with the generic API-reference template above.

## Expected behavior

If a module has a docstring, use it as the page `description`. Only fall back to the generic template when the module has no docstring at all. This was the pre-0.4.5 behavior and the obviously correct default for a documentation generator.

## Workaround (current state)

Consumers must manually restore the descriptions from docstrings in each generated `.md` file's frontmatter after every `selfdoc gen`. This is tedious (70 files for rlsbl alone) and gets silently overwritten on the next run. There is no opt-out today.

## Request

Revert this default. The pre-0.4.5 behaviour (docstring wins, template is the fallback) is what users want.

At minimum, add a config opt-out so consumers can recover the original behaviour without forking:

```json
{
  "prefer_docstring_descriptions": true
}
```

in `selfdoc.json`. But the right fix is to make this the default and only fall back to the generic template when the module has no docstring.
