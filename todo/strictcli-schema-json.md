# Replace AST-based strictcli extraction with .strictcli/schema.json

## Context

selfdoc currently extracts CLI structure from strictcli consumer projects via AST parsing (`strictcli_support.py`). This works but is fragile -- it breaks on dynamic command registration, complex patterns, and requires a separate Go extractor for go-strictcli consumers.

strictcli is adding a `.strictcli/schema.json` file to every consumer project. This is a runtime-generated, authoritative description of the full command tree (commands, groups, flags, args, types, defaults, help text) in a cross-language JSON format.

## Problem

- AST parsing is language-specific (separate Python and Go extractors)
- AST parsing can't handle dynamic registration or computed values
- The schema.json is authoritative (generated by strictcli itself at runtime)
- Maintaining two extraction paths (AST + schema.json) is unnecessary long-term

## Proposed solution

Replace the AST-based strictcli extraction with reading `.strictcli/schema.json`:

1. When `selfdoc gen` encounters a project with `.strictcli/schema.json`, read the schema directly instead of AST parsing
2. Generate the same CLI documentation pages (cli-index.md, cli-*.md) from the schema
3. Remove the AST-based extractors once all consumers have `.strictcli/schema.json`
4. Fallback to AST parsing during transition period (schema.json preferred if present)

## Affected files

- `selfdoc/strictcli_support.py` -- current AST extractor (Python)
- `selfdoc/strictcli_go_support.py` -- current AST extractor (Go)
- `tests/test_strictcli_support.py` -- tests for the extractors

## Effort

Medium -- the schema.json format needs to stabilize in strictcli first. Once it does, the selfdoc side is straightforward: read JSON, generate the same markdown pages. The Go extractor can be deleted entirely.

## Depends on

strictcli `.strictcli/schema.json` feature being implemented and rolled out to all 10 consumer projects.
