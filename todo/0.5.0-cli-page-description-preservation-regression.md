# selfdoc 0.5.0: CLI page descriptions are not preserved across `selfdoc gen` runs

**STATUS: Item 1 (preservation logic) DONE in 0.5.1 — see `selfdoc/strictcli_support.py`
`_read_existing_cli_description` and the per-command, per-group, and index-page generators.
Regression tests added in `tests/test_strictcli_support.py::TestDescriptionPreservation`.**


## Context

selfdoc 0.5.0 added preservation of handwritten frontmatter `description` values for
auto-generated module pages (see `_read_existing_description` in `selfdoc/gen.py` and
the related fix that gated the generic template detection in
`_DEFAULT_DESCRIPTION_PATTERN`).

This works for module pages (`rlsbl-*.md`) and was verified during a 92-page
rewrite of descriptions across the rlsbl docs. Running `selfdoc gen` after
that rewrite left module pages untouched.

However, the same preservation logic is **not** wired into the strictcli CLI page
generator. `selfdoc/strictcli_support.py` (around line 503-518) recomputes the
page description as `chelp[:155]` on every run without consulting the existing
file's frontmatter. As a result, hand-edited CLI page descriptions are overwritten
on the next `selfdoc gen` invocation.

## Reproduction

1. In rlsbl, run `selfdoc gen`. Note the auto-generated descriptions on `docs/cli-*.md`
   are truncated mid-word at 155 chars (e.g. `cli-yank.md` ends in `prepends a deprecation notice`
   with no period).
2. Hand-edit one of those pages, replacing the description with a complete sentence
   under 155 chars.
3. Run `selfdoc gen` again. The hand-edited description is replaced with the
   truncated `chelp[:155]` value.

This was reproduced against rlsbl with selfdoc 0.5.0 installed via
`uv tool install --reinstall selfdoc==0.5.0`.

## Affected files

- `selfdoc/strictcli_support.py` -- the per-command page generator that builds
  `description: "{cmd_desc}"` from `chelp[:155]` without checking the existing
  file. Same issue likely applies to the group page generator that builds
  `grp_desc`.
- `selfdoc/gen.py` already has `_read_existing_description(filepath)` (the function
  used for module pages). This helper is reusable for CLI pages.

## Proposed fix

In `strictcli_support.py`'s page generators (per-command and per-group), import
`_read_existing_description` from `gen.py` and:

1. Resolve the output path for the page being generated.
2. Call `_read_existing_description(out_path)`.
3. If it returns a non-`None` value (meaning the user customized it), use that
   verbatim instead of recomputing from `chelp[:155]`.
4. Otherwise, fall back to the existing `chelp[:155]` truncation.

The existing `_DEFAULT_DESCRIPTION_PATTERN` in `gen.py` only matches module-page
templates, so it will treat any handwritten CLI description as user-customized
and preserve it. If CLI pages ever introduce their own auto-generated default
template, add a sibling regex and check both.

## Why the truncation is wrong on its own

`chelp[:155]` cuts mid-word, leaves trailing partial sentences, and produces text
that selfdoc's own SEO lints rightly complain about. The truncation is a stopgap
for help text >155 chars; the right answer is to either (a) write shorter help
text, or (b) let users override the description per-page. The preservation logic
makes (b) viable.

## Effort

Small. Estimated <30 lines of code touching `strictcli_support.py` only, plus
one regression test that generates a CLI page, hand-edits its description,
re-runs gen, and asserts the description survives.
