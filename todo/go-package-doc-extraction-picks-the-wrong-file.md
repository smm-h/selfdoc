# Go package-doc extraction picks an arbitrary file, and reads comments Go does not

## Problem

`selfdoc_core/extractors/go.py` extracts a Go package's doc comment with
`_extract_package_doc` + `_collect_comment_block_above`. Two defects combine to
make `:-: list-modules` render a false description for a package.

**1. The blank-line rule is inverted.** `_collect_comment_block_above`
documents itself as "Skips blank lines between the comment block and the
declaration". Go's rule is the opposite: a comment block is the package's doc
comment ONLY when no blank line separates it from the `package` clause. A
generated file conventionally opens with

```go
// Code generated by scripts/gen-something.sh -- DO NOT EDIT.

package foo
```

which Go does not treat as a package doc (the blank line detaches it) but
selfdoc does.

**2. File order is `os.listdir` order.** `module_docstring` builds
`file_contents` from `os.listdir(pkg_dir)`, and `_extract_package_doc` returns
the first file that has a `package` clause with a comment above it. That order
is filesystem-dependent, so which file wins is arbitrary — and it changes when
unrelated files are added to the package.

Together: a package whose real doc comment lives in one file, and which also
contains a generated file with a `DO NOT EDIT` header, renders as

```
- **.**: Code generated by scripts/gen-something.sh -- DO NOT EDIT.
```

instead of the package's actual synopsis. This was previously rendering
correctly in the same repository and flipped when a generated file was added to
the package — nothing about the doc comment changed.

Because `list-modules` is used inside `root_files` templates, the false line
ends up committed in a generated `CLAUDE.md`/`README.md`.

## Reproduction

A directory with two non-test `.go` files in package `foo`:

- `doc.go`: `// Package foo does X.\npackage foo`
- `zz_generated.go`: `// Code generated by gen.sh -- DO NOT EDIT.\n\npackage foo`

`GoExtractor.module_docstring(dir)` returns whichever of the two `os.listdir`
yields first. Correct answer: always "Package foo does X."

## Fix

Two independent changes, both small, in
`selfdoc_core/extractors/go.py`:

1. `_collect_comment_block_above` must NOT skip blank lines when the target is
   a `package` clause — a blank line between the comment and `package` means
   there is no package doc in that file. (For other declarations the current
   skipping may be intentional; if so, take a `skip_blanks` parameter and pass
   `False` from `_extract_package_doc`.)
2. `_extract_package_doc` must iterate `file_contents` in a deterministic
   order, and prefer the conventional doc file: `doc.go` first, then the file
   named after the package, then the rest sorted. `module_docstring` should
   sort `os.listdir` before building the dict regardless.

A generated-file header is also worth skipping explicitly: a comment block
matching Go's own `^// Code generated .* DO NOT EDIT\.$` marker is never a
package doc, whatever its position.

## Tests

- A package with a `doc.go` and a generated file whose header would otherwise
  win, asserted to extract the real synopsis. Fails today depending on
  filesystem order, so build the dict explicitly in both orders and assert the
  same answer from each.
- A package whose only comment is a generated-file header separated by a blank
  line, asserted to extract the empty doc (no doc comment) rather than the
  header.
- A regression test at the `list-modules` level: a rendered bullet for such a
  package must carry the package synopsis, not the generated-file marker.

## Affected files

- `selfdoc_core/extractors/go.py` (`_extract_package_doc`,
  `_collect_comment_block_above`, `GoExtractor.module_docstring`)
- `selfdoc_core/content.py` (`_list_modules_by_package`) — consumer, likely
  unchanged
- `tests/` — new cases per above

## Effort

Small: two focused changes plus tests. The risk is in change 1 — check every
caller of `_collect_comment_block_above` before flipping the blank-line
behavior globally, and prefer the parameterized form if any caller relies on
the skipping.
