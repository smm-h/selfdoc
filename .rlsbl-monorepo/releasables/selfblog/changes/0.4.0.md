## 0.4.0

The assembly deploy is a command behind a thin generated workflow, the site answers on one canonical hostname with a generated redirect map, a declared home project is served at the site root, and every project's posts share one site-level blog/ namespace.

<details>
<summary>Context</summary>

One program across all three packages: the site's addressing, the assembly that
serves it, and the authoring checks that keep it honest.

Addressing changed first. A page's current version now lives at a stable,
unversioned address and superseded versions are archives under v/, declared as
such in canonicals, sitemaps and feeds. Posts moved to one site-level blog/
namespace shared by every project. Every link, canonical and sitemap entry the
build emits is now resolved against the files it actually wrote (LINK001), and
the assembly worker carries a redirect map generated from the manifests, so the
retired address schemes still land somewhere real in a single hop.

The assembly stopped being CI shell. The deploy body is a command
(assembly integrate), the workflow that calls it is a thin generated artifact
whose tool pins are rewritten and checked against PyPI on every sync, and the
assembled tree is verified before anything is pushed. Membership is a declared
roster with a required home project served at the site root, documentation can
be published without a release, and a project can be retired.

The authoring checks grew a spine: every emittable lint code is declared in a
registry with its severity, suppression is validated against that registry and
can no longer silence an error, posts are linted like pages, and prose is
spell-checked -- including the prose a directive renders out of an authored
document.

Search switched to Pagefind and the builtin engine was deleted, so
search_engine is required and names the one valid value. The author block is
required too: one Person is built from it rather than an Organization invented
from a directory name.

Breaking changes are minor bumps under the pre-1.0 convention; each is a
breaking-type entry in the changelog.

</details>

### Breaking

- [selfblog] **`selfblog check --ignore` refuses a code the lint registry does not carry.** A mistyped code silently suppressed nothing; the flag is validated against the registry before any check work runs, and an unknown code aborts naming the known codes.
- [selfblog] **A release no longer destroys documentation published between releases.** A full build replaced the project's whole section in the assembly, so a post or a documentation update published since the last release died at the next one. Each publisher now records the files it produced and removes only the ones it produced before and no longer produces -- a page the build dropped still disappears, everything else stays. Assembly membership moved to a hand-edited `roster.toml` in the assembly repository that every deploy reconciles to: a project that leaves the roster loses its section, its manifests, its membership record and its search-index entries, and a dispatch can no longer add a project by arriving. The file is required, and a deploy without it stops with instructions.
- [selfblog] **The unified site follows the new addressing scheme, and every project's posts land in one `blog/` tree.** Each constituent mounts its current version at `<slug>/` and its superseded versions at `<slug>/v/<version>/`; the locale segment is gone while there is one locale. Posts are site-level: whichever project wrote one, it is emitted at `blog/<slug>/`, so a slug repeated across projects is a hard error naming both.
- [selfblog] **`selfblog check --ignore` refuses error-severity lint codes.** Suppression reaches warnings only; naming an error code is a hard error that names the code and its severity and stops before any checking runs.
- [selfblog] **Every post declares whether it may contain directives.** Post frontmatter gains a required `directives` boolean with no default: a post that omits it is refused at discovery (POST006). A post declaring false that carries a directive marker is refused too (POST007), naming the marker and the line of the post file it sits on -- markers inside fenced code blocks and backtick code spans are examples of the syntax, not uses of it, and never count. A post declaring true resolves its directives like any other page. `selfblog post new` and `selfblog post generate --from-release` emit the key; every existing post has to add it.
- [selfblog] **Posts no longer carry a `project` frontmatter field.** Nothing read it: the key was written by `selfblog post new` and `selfblog post generate --from-release`, carried onto the parsed post, and consulted by no build, manifest, listing, feed or assembly path. Both scaffolds stop emitting it; an existing post that declares it can drop the line.
- [selfblog] **The assembly declares one home project, served at the site root -- and the `--portfolio-file` path is gone.** `roster.toml` gains a required top-level `home` key naming one declared project: its pages are emitted at the site root instead of under `site/<slug>/`, it is left out of the generated project listing and out of nav, and retiring it is refused. A roster with no home, or a home naming an undeclared slug, is a hard error -- a site needs a front page and no project is picked by default. The generated listing moved to the fixed address `/projects/`. What this replaces: a hand-written HTML file copied into the site root, its `assembly.portfolio_canonical` config field, the regex that spliced a canonical link into it, and the flags carrying it through `generate-shared` and `integrate`, all removed. The front page is a real project's real page now.
- [selfblog] **One hostname.** Every request on a host other than the canonical one is 301'd to the same path on it, query preserved -- so no path is served on two hosts. The retired blog subdomain keeps its `/blog` prefix on the hop, because its whole document space was the blog.
- [selfblog] **A missing curated listing stops the deploy instead of inventing one.** When the home project's `docs/projects.toml` sidecar had not reached the assembly, `/projects/` was published as every project in name order -- a listing nobody curated, at the curated one's address. Shared generation now fails, naming the missing file and the deploy step that writes it.

### Features

- [selfblog] **Assembly deploys are a command, not embedded CI shell.** `selfblog assembly integrate` performs the whole deploy body -- version detection, subtree replacement, artifact filtering, membership bookkeeping, the push retry loop and search indexing -- and the generated workflow is six thin steps that invoke it. `selfblog assembly sync-workflow` regenerates the deployed workflow on every release and pins the selfblog version it installs, so it can no longer drift from the generator. The Git Data API push path now carries binary content, skips files whose bytes already match the remote, and can delete paths. `assembly push` resolves the tag that names the version being dispatched instead of the repository's newest tag, and refuses to dispatch a version missing from selfdoc.json's versions.
- [selfblog] **`parse_post` is public.** Post validation, slug derivation and metadata now live in one function that works on any markdown source, not just a file on disk.
- [selfblog] **`assembly sync-workflow` refuses a pin PyPI cannot serve.** The selfblog pin defaults to the running selfblog, which in a checkout is an editable install ahead of the registry, so the written workflow could carry a `pip install selfblog==X` that resolves nowhere -- surfacing later as a failed deploy on the assembly repository. Every pin is now checked against PyPI before anything is written, and an unpublished one aborts the run naming the version and the registry.
- [selfblog] **Two new ways to change what the assembly serves, neither of which needs a release.** `selfblog docs publish` is the documentation counterpart of `post publish`: it builds locally and pushes the project's section, its manifest and its membership entry into the assembly repository in one commit, images and all, deleting the pages the project no longer builds as it goes, then dispatches a rebuild of the shared elements. `selfblog assembly retire --slug <slug>` does the opposite and was previously impossible without hand-editing the assembly: it removes the project from the roster and deletes its whole section and every one of its manifests in one commit, so the listing, feed, sitemap and search index stop naming it. Both are consequential.
- [selfblog] **The assembled site is verified before the deploy pushes it, and `selfblog assembly verify` runs the same assertions by hand.** One read-only pass over the built tree checks that the roster, the subtrees and the manifests name the same projects, that every page and post a manifest lists was emitted, that the shared artifacts exist and parse, that every internal reference, sitemap entry, feed link and cross-project link resolves, that every page has a title and a canonical under the site's base, and that no unresolved directive or per-project routing file survived. A broken tree now fails with nothing deployed. The assembly also writes its own `robots.txt` and root 404, which previously ended up buried under each project's prefix.
- [selfblog] **The front page is authored, and its mechanical parts are directives.** The home project's pages may carry `:-: projects-cards` and `:-: blog-highlights limit="N"`, which render the curated project listing (with each project's live version) and the recent posts across the whole site. The listing itself is authored in the home project at `docs/projects.toml` -- categories, per-project blurbs, optional external entries -- and validated strictly: an unknown key, a missing blurb, a duplicate slug and a listed slug the assembly has no manifest for are each a hard error naming the offender, while a roster project the listing omits is legal, because curation is selection. The generated `/projects/` page and the front page's cards are two renderings of that one file. Both resolve twice from the same code: at build time through `selfblog build --target home --site-manifests <dir> --docs-base <url>`, and again on every deploy, so a version badge on the front page is as current as the last deploy of the project it names rather than the last deploy of the home project. A build with no assembly data refuses instead of emitting an empty region.
- [selfblog] **Retired addresses redirect, and the site root serves an llms.txt.** The worker carries a redirect map generated from the manifests: `/<slug>/<locale>/<version>/<rest>` collapses to `/<slug>/<rest>` for any version, and `/<slug>/posts/<post>/` becomes `/blog/<post>/`; a path naming no real project or post falls through to the 404 instead of guessing. Alongside it, the assembly root now serves an `llms.txt` linking to each project's own by reference, with its name and description, plus the blog.
- [selfblog] **The assembly's own pages carry the search dialog.** The blog index, the project listing and the site 404 answer Cmd/Ctrl+K from the site-wide Pagefind index, like every documentation page. `wrap_shared_page` takes a mandatory `search_prefix` -- the hop from the page back to the site root. The home project's own index is dropped at the graft, since its pages sit at the site root and answer from the site-wide index the assembly builds over the whole tree.
- [selfblog] **A curated project entry may declare `repo`.** The repository is rendered as a second link on the project's card, beside the one its title carries. Declaring the same address as both `url` and `repo` is refused.

### Fixes

- [selfblog] **Unified site pages address their own mount.** Constituent projects on a unified site mount at `<locale>/<slug>/<version>`, and page addressing now carries the project segment, so asset links, canonicals and hreflang on a unified page resolve to real files instead of paths one or two levels short.
- [selfblog] **`selfblog check` honors the configured coverage threshold.** The unified path demanded that every public symbol be documented regardless of `coverage_threshold`, so a project that lowered the threshold passed `selfdoc check` and failed `selfblog check` on identical state. Both entry points now reach the same verdict.
- [selfblog] **Post checks no longer need the selfdoc package.** `check_posts` reads POST001-POST005 severities from the lint registry in selfdoc-core instead of importing `selfdoc.check`, so a posts-only install runs them with selfblog alone.
- [selfblog] **An assembly dispatch must name the version the build will actually produce.** `assembly push` accepted any version present in `selfdoc.json`'s `versions`, so dispatching an older one published the newest version's docs recorded under the older version's name. The dispatched version now has to be the newest declared one, and the refusal names both. A blank newest `versions` entry -- previously refused only when a second entry existed, and otherwise built unversioned at the wrong address -- is a hard error however long the array is.
- [selfblog] **An assembly rebuild refuses an incomplete membership record.** `assembly rebuild` turned a missing version into the literal string `latest`, which travelled through the dispatch payload and back into the assembly's own `projects.json`. A record missing `repo`, `ref` or `version` is now a hard error naming the project and the missing fields.
- [selfblog] **The generated deploy workflow pins every tool it installs.** selfdoc and pagefind floated on the same install line that pinned selfblog, so a released change to either could break every project's deploy at once -- the exact failure the selfblog pin exists to prevent. All three are pinned now and rewritten on every `assembly sync-workflow` run, with `--pin-selfdoc` and `--pin-pagefind` to name them explicitly.
- [selfblog] **The unified landing page's links resolve.** The projects page at `<locale>/common/<version>/projects/` asked for `../style.css` (the stylesheet is at the site root) and gave each project card a site-root path with no relative hop, so neither the styling nor any card worked. Both now come from the landing page's own address.
- [selfblog] **A post slug repeated across two projects is refused when the assembly merges them, naming both.** Posts share one slug namespace across the assembled site, but each project's posts arrive as its own manifest, so no single build ever saw two projects' posts together: the blog index, the feed and the sitemap silently disagreed. All three now merge through one function that refuses the collision, and the assembly has one address authority those generators, the cross-project link check and the deploy-time verification all read.
- [selfblog] **Posts are served at `/blog/<post-slug>/`, at the site level, and the deploy publishes them there.** The graft copied a project's whole build into its own subtree, so a post landed at `/<slug>/blog/<post>/`; the blog index linked `/<slug>/posts/<post>/`; and the posts-only deploy read a directory the build no longer emits, publishing nothing and then removing the posts it had published before. All three now agree on the one address the build emits: the graft splits a build's output between the project's subtree and the site-level blog, a project's own blog listing page is not grafted over the assembly's, and a posts-only publish that produced no posts says so and removes nothing. Retiring a project takes its posts off the blog with it, and a deploy refuses to overwrite a post another project claims.
- [selfblog] **`selfblog post publish` records the posts it publishes.** An out-of-band post publish wrote no published-file record, leaving its posts unclaimed: nothing accounted for them, another project's publish could overwrite them, and retiring the project left them behind on the blog. The publish now updates the posts owner's claims (schema v2, site-level `blog/<post-slug>/` paths) in the same commit that carries the files, and removes the posts it claimed before and no longer produces. A build that emitted no post pages leaves the record untouched.
- [selfblog] **A failed read of the assembly no longer looks like an absent file.** A rate limit, an expired token, a 5xx or a network failure while `docs publish`, `post publish` or `assembly retire` read the assembly used to return the same empty result a genuinely missing file returns, and the publisher wrote a fresh record over what it had failed to read -- destroying another publisher's claims, or leaving a retired project's posts on the blog. Only an explicit 404 is absence now; every other failure stops the operation before anything is written, naming what was being done and what GitHub said.
- [selfblog] **`assembly verify` checks the search index instead of the pagefind directory.** Any file at all under `pagefind/` counted as a built index, and pagefind writes its runtime JS whether or not it indexed a page -- so a site that answered no searches passed. It now requires `pagefind-entry.json` to be present and parseable, to declare at least one language, to report at least one indexed page, and at least one per-page fragment to exist.
- [selfblog] **`docs publish` and `post publish` refuse to overwrite another project's post.** The site-level blog is one namespace, so two projects that pick the same post slug address the same file. Only the assembly-side graft checked for that; both remote publishers wrote straight onto the deployed branch without looking. They now read the other declared projects' published-file records first and refuse, naming both projects and every colliding path.
- [selfblog] **A real root 404.** The assembly's `404.html` says what happened and links home, the project listing and the blog, instead of reading like the front page.
- [selfblog] **A unified build no longer ships the deleted builtin search.** It wrote a `search-index.json` and a `search.js` built from the builtin engine even for a site that declared Pagefind. It now runs Pagefind over the whole unified output, one index for every constituent project.
- [selfblog] **A redirect never lands on another redirect.** The assembly worker applied its historical-address map once, so a retired address whose target was itself a retired address answered with a 301 to a 301. The map now runs to a fixpoint, and every emitted redirect reaches its page in one hop.
- [selfblog] **`assembly verify` refuses a sitemap entry on another host.** A `<loc>` outside the site's canonical base passed verification silently, so a stale or foreign address could be submitted to crawlers as this site's. Every sitemap entry is now checked against the canonical base and a foreign one fails, named.
- [selfblog] **A roster with an empty `home` says so.** An absent `home` key and a `home = ""` shared one message that told the author to add a key already in the file. The absent key, the empty value and a home naming an undeclared slug now each report their own mistake.
- [selfblog] **A post's error points at the post.** POST001-POST007 reported the posts directory with no line, leaving the real file and line legible only inside the message text. Editors, CI annotations and the JSON output now get the offending post's path, and the stray-marker error its line.
- [selfblog] **`selfblog check` and `selfblog build` refuse a bad config cleanly.** Both read `selfdoc.json` with no handler, so an unusable one ended the command on a traceback; the home and unified builds did the same for a directive nothing answers. Each now prints one `Error:` line and exits 1.
