## 0.38.1

Fixes the CLI reference pages selfdoc generates failing selfdoc's own spell check: the entity indent on a scoped flag row and the 'Clearable' heading of a sparse update.

<details>
<summary>Context</summary>

selfdoc renders a strictcli app's schema into reference pages and then
spell-checks those pages, so every fixed word and every markup construct the
renderer emits is judged by SPELL001 in the consumer's project. Two of them
were not words the engine knew: the '&nbsp;' entity that indents a scoped
flag's row under the member it belongs to, and the '- Clearable:' heading a
sparse update publishes its unset tokens under. The first project to render a
member-spelled selector and an update command with a nullable property got 37
error-severity lints for text it did not write and could not edit.

Both are fixed in the engine (selfdoc-core 0.10.1), each at the layer it
belongs to: entity references are markup and are blanked like tags before a
line is scanned, and the fixed vocabulary selfdoc's own renderers emit is
carried by the engine and accepted everywhere, because the accept list belongs
to one machine while a rendered page ships to all of them. A rendered-page test
renders a schema exercising every construct the renderer has prose for, so a
new fixed word cannot reach a consumer unaccepted.

</details>

### Fixes

- [selfdoc] **`selfdoc check` no longer fails on the CLI reference pages selfdoc itself generates.** A command declaring a member-spelled selector rendered its scoped flags behind `&nbsp;` indents, and a sparse update rendered a `Clearable` heading; the spell checker read both as English, so a project that regenerated its CLI reference got error-severity lints for text it did not write and could not edit.
