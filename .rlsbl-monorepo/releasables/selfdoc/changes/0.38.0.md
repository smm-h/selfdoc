## 0.38.0

CLI reference pages read strictcli schema version 2, and selfdoc's own CLI declares its presence

<details>
<summary>Context</summary>

strictcli 0.41.0 turned a set of previously-inferred facts into mandatory
declarations, every one of them a registration-time hard error, and it
publishes the result at schema_version 2. Both halves reach selfdoc.

Its own CLI could not start under 0.41 until every flag and argument
declared its presence, which is what makes selfdoc runnable at all for a
fleet already on the new floor -- selfdoc gen and selfdoc check are steps
in every project's release, so nothing downstream could release until
this shipped.

Its reader of other projects' schemas was worse than broken: it read a
`type` key v2 deleted and a `required` key an earlier round deleted, and
both reads had a fallback, so every page claimed every flag was a string
and every positional argument required, silently and successfully. The
reader is now v2-only and refuses any other version rather than guessing,
and it renders the constructs v2 adds -- presence, choices records,
selectors and their scopes, constraints, update declarations -- instead of
flattening them away.

</details>

### Breaking

- [selfdoc] **Breaking: machine output is now the strictcli envelope, entered with `--json`.** `selfdoc check`, `selfdoc spell-corpus` and `selfdoc quality` no longer take `--format text|json`; each writes exactly one document to stdout under `--json` — the framework envelope, whose `payload` member is the report. Each command declares its payload's JSON Schema, which the framework validates before writing and `--dump-schema` publishes, so `schemas/check-output.schema.json` is gone: the declaration is the artifact to generate against.
- [selfdoc] **Generated CLI reference pages now require strictcli schema version 2.** selfdoc reads `.strictcli/schema.json` at `schema_version: 2` only, and refuses any other version with a message naming the regeneration command. v2 is not a superset of v1 -- it deletes keys the old reader read -- so there is no dual path: regenerate the schema with a strictcli 0.41.0 or newer (`<app> --dump-schema`).

### Features

- [selfdoc] **A guide for the new blog-post editor.** `docs/editor-guide.md` documents the authoring app: the registry file's format and every shape it refuses, the two commands and their flags, where the editor's front-end assets come from, and what the preview is -- the publish render of an unsaved buffer, and why that means it writes nothing.
- [selfdoc] **The editor guide covers the assistance lanes, cross-project links and publishing.** New sections describe the spelling and lint marks and where their engines come from, the `](` completion and the addresses it inserts, and the publish consent dialog -- including that it publishes the whole repository and that consent is never remembered.
- [selfdoc] **Glossary guide covers every declaration form.** The guide now documents Markdown definition lists alongside `<dfn>` tags and the `list-glossary` directive, states that prose is never read as a declaration, and describes the `term-<slug>` anchors and the link from a definition site back to its glossary entry.
- [selfdoc] **The blog guide covers the local assembly preview.** A new section documents the command surface, the pipeline table naming which production function runs at each step, that verification reports rather than blocks, what the server does about directory addresses and 404s, and why the output directory is refused inside a checkout.
- [selfdoc] `selfdoc build --theme <name>` renders the site under a named theme for that build only, overriding what `selfdoc.json` declares and writing nothing back. An unknown name is refused against the theme registry.
- [selfdoc] **The theming guide describes the tinymoon theme as it now is.** It said the theme carries its own base64 faces and defines its own palette; it now covers the framework composition, the variable bridge, the CSS-only three-state resolution and the `css/` + `fonts/` layout.
- [selfdoc] **Documented which pages print their frontmatter description above the H1.** The getting-started guide now states the rule: the home page and posts drop the summary block, every other page keeps it.
- [selfdoc] **CLI reference pages render the constructs strictcli schema v2 publishes.** A value flag's `choices` appear with their per-entry help. A selector renders as the construct it is: a member-spelled one's own name is never printed as a flag, because it is never typed -- each member becomes its own row, with the flags that exist only while it is elected indented beneath it, to any depth, each naming its scope. Constraints render as the rule each one states. An update command states its resource, its write mode, what an unsupplied property means, that at least one property is required, and the `--unset-<property>` spellings a nullable property mints. A negatable bool shows `--no-<flag>` beside its own name, and flag sets and the app's config and env-prefix declarations reach the page too.
- [selfdoc] **selfdoc requires strictcli 0.41.0 or newer, and its own CLI is declared on the new terms.** Every flag and positional argument declares its presence, so `--help` states which of required, optional or a declared default each one is. What you type is unchanged: an omitted `--auto-commit` still commits, an omitted `--port` still binds 8000, and each such flag now names its fallback in its own help text.

### Fixes

- [selfdoc] **`selfdoc init` no longer invents a version.** A codeless project gets `"unversioned": true` instead of a placeholder `0.1.0` that was rendered as a topbar badge and offered as a search filter; a project with code whose manifest states no version is refused rather than given a made-up number.
- [selfdoc] **`selfdoc check` reports a visible link that names the site's own base.** An `<a href>` written absolutely against the configured base resolves on the deployed host and nowhere else, so it works on a preview by leaving the preview -- the file-existence half of `LINK001` could never see it, because the page it names really is there. It is now reported beside the origin-absolute rule. A project the site mounts under a slug passes that mount to the check, so its subtree is not asked to resolve references into the site around it.
- [selfdoc] **Fixed: `selfdoc quality` no longer reports a silent zero when the source-line scan fails.** It read dirstat's output inside a bare `except` that returned zero LOC on any failure, which graded every project an A on an infinite documentation ratio. A scan that cannot be run, times out, or answers in an unreadable shape is now a hard error naming the cause — submodule subtractions included.
- [selfdoc] **CLI reference pages stop calling every flag a string and every positional argument required.** The reader was looking up a `type` key schema v2 deleted and falling back to `str`, and a `required` key an earlier strictcli deleted and falling back to `true`, so a page could label an int flag `str` and an optional argument required without anything failing. Both now come from the declaration: `value_schema` gives the type word (`str`, `bool`, `int`, `float`, `list[T]`, `dict[str, T]`) and `presence` gives a Presence column stating exactly one of required, optional or a default value.
