## 0.10.2

Published validators regenerated against the current strictspec runtime, so registry installs import again; project-name detection honors the declared source language in polyglot repositories.

<details>
<summary>Context</summary>

The validators shipped in the previous release were generated by strictspec
0.1.0; strictspec's runtime pairing is an exact version match and floor-only
dependencies resolve the newest runtime, so every registry install of this
package has failed at import since strictspec 0.2.0 shipped. The regenerated
validators and the matching strictspec floor were committed weeks ago and
never released; this release ships them.

</details>

### Fixes

- [selfdoc-core] **Project-name detection honors the declared source language.** `_read_project_field` reads the repo's selfdoc.json source declaration and resolves the name from that language's manifest (go -> go.mod, python -> pyproject.toml, js -> package.json) before falling back to the fixed lookup chain — so a polyglot repo's incidental manifests no longer win.
- [selfdoc-core] **Version detection reads the manifest your project actually declares.** A Go project with an unrelated `package.json` at its root (a browser-test harness, conventionally at version `0.0.0`) no longer reports a version-consistency mismatch: the source language declared in `selfdoc.json` picks the manifest the version comes from -- `go` reads `VERSION`, `python` reads `pyproject.toml`, `js`/`node` read `package.json` -- matching the rule already used for the project name.
- [selfdoc-core] **The list-modules directive honors your `gen.exclude` patterns.** A module listing walked the whole source tree with no exclusions, so it advertised modules the generated site has no page for -- an analyzer's `testdata` fixture tree being the case that surfaced it. Listings now apply the same default and `gen.exclude` patterns page generation applies, from one shared authority, on every language path.
