## 0.9.2

A reference crossing a shared site's mount names the root that serves it

<details>
<summary>Context</summary>

A mounted project is served two roots at once: its documentation under its
slug, its posts at the site root. The earlier mount fix covered one surface,
the sidebar's project-page-to-post link, and left three writing a relative hop
into nothing -- cross-page term links in both directions, the auto-glossary's
Source link to a term defined in a post, and every project-page reference a
post itself writes. The hop is now chosen per reference from the root the
target belongs to, and the grafted-assembly fixture defines a term on each
side of the boundary so the deploy's own verification sees them.

</details>

### Fixes

- [selfdoc-core] **Links between a project's docs and its posts resolve on the unified site.** A project served under a shared site's mount is served two roots at once -- its documentation under its slug, its posts at the site root -- and a reference crossing between them is now written against the root that serves the target. Cross-page term links, the auto-glossary's Source links, and every reference a post writes back into its own project used to name addresses the site does not serve.
