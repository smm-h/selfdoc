## 0.40.0

Pages describe their project to search and answer engines: index titles name what the project is, social titles match, the assembled site links every project from every page and its listing pages carry descriptions and structured data, robots.txt allows Claude-SearchBot, and the crawler list, description lints, Go synopsis extraction and stale-build link reporting are corrected.

### Features

- **robots.txt now allows `Claude-SearchBot`.** Anthropic's indexing crawler for Claude's search is named explicitly alongside the other AI crawlers, so generated sites are indexable by it.
- **The assembled site's listing pages are now legible to search engines.** `/projects/` and `/blog/` carry a meta description and `CollectionPage` structured data with breadcrumbs, and the 404 page asks not to be indexed.
- **Every page on the assembled site now links the site's other projects.** A "More tools from this site" section at the end of each page names each one with its one-line description; a project deployed on its own emits nothing.
- **Assembly verification now refuses a site where a project is unreachable.** A deploy fails if the site root or the `/projects/` listing does not link a declared project's index page.

### Fixes

- **A project's index page title now says what the project is.** A page titled with the project name rendered `name - name`, which no search or answer engine can use. It now renders the project name followed by the thing the `description` in selfdoc.json names (the part before its ` that ` clause), trimmed at a word boundary to at most 70 characters; a description with no such clause leaves the project name alone, and `selfdoc check` reports the new SEO016 warning.
- **Meta description warnings now use a 110-160 character band.** `selfdoc check` warned about any description under 120 characters (SEO009) or over 155 (SEO010); the band is now 110-160, which matches what a search result actually renders. Nothing truncates a description, so what you write is what the page publishes.
- **A generated file's `DO NOT EDIT` banner no longer becomes a Go package's description.** `selfdoc gen` read any comment above a `package` clause, including one separated from it by a blank line, so a package containing a generated file got a page described as "Code generated by ...". Only a comment adjacent to the package clause counts now, which is the rule `go doc` applies.
- **The site-wide `llms.txt` marks a project with no description.** An entry whose manifest states none now reads `(no description)` instead of stopping after the link, so the gap is visible.
- **`selfdoc check` no longer reports links from an out-of-date build.** After a source doc comment changed, check kept reporting the link the previously built page carried (LINK001) until `selfdoc build` was re-run, an error no source edit could clear. A reference inside a page's content region that the page's current source no longer carries is now skipped.
- **The sibling-projects section is styled.** The "More tools from this site" block every assembled page ends with now renders as a compact grid of project links with muted one-line descriptions, separated from the article by a border, instead of a bare heading over a bulleted list.
- **The llms.txt guide lists the crawlers your build actually allows.** The "AI Crawler Access" section now renders the user agents straight from the crawler policy `robots.txt` is generated from, via a new `list-crawlers` directive, instead of a hand-written copy that could fall out of step with the file.
- **The project describes itself with a defining first sentence, and its docs base is the unified-site address.** The README opened with a fragment and the declared docs base was the retired per-project host.
- **Social titles no longer repeat the project name.** A page titled with the project name -- the home page -- published `og:title` and `twitter:title` as `<name> - <name>`; both now carry the same title the page's `<title>` element shows.
- **`selfdoc check` reports a broken link again.** The stale-build filter compared a built page's href (`../missing/`) against the page's Markdown (`[Guide](missing.md)`) -- two spellings that never match -- so LINK001 was suppressed on links the source really does write. The filter now compares against the hrefs the current source would emit.
- **The title-length check now measures the title a page really renders, and the cap is 60 everywhere.** SEO004 modelled every title as `<page title> - <project name>`, so on the home page -- whose title is the project name -- it reported a length no page carried, and no edit could clear it. It now measures the rendered document title, and the derived home-page title is cut to 60 characters rather than 70, matching the check's own threshold.
