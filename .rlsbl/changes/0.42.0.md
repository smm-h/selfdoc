## 0.42.0

Every selfdoc-owned directory lives under .stricttools/ with a manifest.toml per directory, moved by a dry-run-capable script; titles compose written values only; topology.projects, legacy_blog_host and the Pages worker are gone; the lint table renders from the registry; check resolves generated pages through both docs roots.

### Breaking

- **Breaking.** Every directory selfdoc owns in a repository moved under one hidden directory, `.stricttools/`: the handwritten pages at `.stricttools/docs/`, the generated pages and the manifests, hash baselines and revisions at `.stricttools/docs-state/`, the build output and version cache at `.stricttools/docs-cache/`, the posts at `.stricttools/posts/`, and the vocabulary at `.stricttools/vocabulary/`. A repository still carrying `.selfdoc/` or declaring a docs, output or posts path outside the layout is refused by every command, with `scripts/move-to-stricttools-layout.py` named. Writing into any of those directories needs that directory's own `manifest.toml` -- one line, `owner = "selfdoc"` -- which selfdoc never writes itself and refuses without, printing the file and the line to create.
- **Page titles are written text.** A page's `<title>` is now composed of written values only -- the page's own title, the project's name, and the name of the assembled site -- joined with ` - `, with an empty or repeated name left out so no title renders `X - X`. A project's index page names no project, so a standalone build's front page carries its written title alone; it no longer draws on the project `description`, and the SEO016 lint that asked that description to carry a ` that ` clause is gone. `og:title` and `twitter:title` carry the same string the title element does.
- **`topology.projects` is refused.** A cross-project link now resolves to `<topology.docs_base>/<slug>/` for any slug, so the hand-typed slug-to-URL map is gone from the schema and from the URL builder. A `selfdoc.json` still carrying `topology.projects` is refused by name, saying what replaced it.
- **No redirect worker is emitted.** The assembly no longer generates a Cloudflare Pages `_worker.js`: host redirects belong to the DNS zone and a retired path shape answers with the site's 404. `--legacy-blog-host` is removed from `assembly init`, `generate-shared`, `integrate` and `preview`, and a `selfdoc.json` carrying `topology.legacy_blog_host` is refused by name. A tree still holding a worker from an earlier deploy is refused by `assembly verify` and deleted by the next integration.

### Features

- **New commands.** `selfdoc layout dump` prints selfdoc's layout declaration as JSON -- every directory it claims under `.stricttools/`, whether the directory is handwritten or generated, whether the repository commits it, the `manifest.toml` that grants it and the exact line that file must hold, and the paths it replaced -- and `selfdoc layout validate` checks one repository against it: every directory carries a manifest naming a tool the machine has, every directory selfdoc claims names selfdoc, each holds only what its side allows, nothing inside starts with a dot except the derived `.gitignore`, and that file carries what the commitment declarations render.
- **New script.** `scripts/move-to-stricttools-layout.py` moves one repository onto the `.stricttools/` layout: dry-run capable, it moves every tracked file with `safegit mv` as one commit, rewrites the paths the moved content names as a second commit, and refuses to finish unless the build that follows publishes the identical URL set.
- **New page.** The documentation now carries a page on the `.stricttools/` layout: the directories selfdoc claims with their sides and commitments, the per-directory `manifest.toml` that grants each one, the derived ignore file, the two docs roots and the addresses they share, `selfdoc layout dump` and `selfdoc layout validate`, and the move script.
- **Ownership is a manifest inside each directory.** A directory under `.stricttools/` declares its owner in its own `manifest.toml` -- one line, `owner = "<tool>"`, validated against a schema so an unknown key is refused -- and that file is the permission to write into it. selfdoc never writes one, refuses a directory that carries none with the exact file and line to create, and treats a manifest naming another tool as that tool's. `selfdoc layout validate` holds every directory under the root to a manifest whose owner is a tool the machine has, and `scripts/move-to-stricttools-layout.py` writes the manifests of the directories it moves content into as part of the move commit.

### Fixes

- **The project description says what selfdoc is.** `selfdoc.json`, the README's opening paragraph and the command's doc comment now carry one written line -- a static site generator that builds a project's documentation site directly from its source code, with SEO/AEO, a first-class blog, search and cross-project linking -- instead of three paraphrases of it.
- **`selfdoc check` no longer reports generated CLI pages missing.** A strictcli project's CLI reference pages are generated into selfdoc's own generated docs root, but the check looked for them only in the handwritten root, so every command's page was reported missing with CLI001. The check now resolves pages across both roots, the way the build does.
- **New directive `list-lints`, and the check guide's lint table is now generated.** The page listed every lint code, its severity and what it checks by hand, so a code added or changed in severity left the documentation stating the old thing. The table is now rendered from selfdoc's own lint registry, and any project's page can render it with `:-: list-lints`.
